# Verifying Phase 3 against local Postgres

The automated test gate (`mvn test`) runs against in-memory **H2** with Flyway **off**, so it
does **not** exercise the real Flyway migrations (`V1..V4`) or Hibernate's production
schema `validate`. This runbook verifies the Postgres-only path end-to-end — the
`V4__iv_history.sql` migration and the **Phase 3 AC5** ATM-IV accumulation job — against a
real Postgres via Docker. Every command below was run and confirmed on
PostgreSQL 16 (see expected output inline).

> Full local dev (desktop, secrets, etc.) lives in [`README.md`](README.md). This doc is the
> narrow "did the DB layer actually work" loop.

## Prerequisites

| Tool | Version |
|------|---------|
| Docker + Compose | Desktop 4.x (`docker compose version`) |
| JDK | 21 |
| Maven | 3.9+ |

## TL;DR

```bash
docker compose up -d                       # 1. start Postgres (waits healthy)
(cd backend && mvn spring-boot:run)         # 2. boot → Flyway migrates V1..V4, Hibernate validates
#   ...verify (see below), then Ctrl-C to stop the app
docker compose down                         # 3. stop Postgres (keep data)
```

---

## 1. Start Postgres

`docker-compose.yml` at the repo root starts Postgres 16 with the same credentials the
backend defaults to (`terminalone / terminalone @ localhost:5432`).

```bash
docker compose up -d
```

Wait until the container reports healthy:

```bash
docker inspect -f '{{.State.Health.Status}}' t1-pg      # -> healthy
```

## 2. Boot the backend (runs the migrations)

On startup the backend runs **Flyway** (migrates `V1..V4`) and then boots Hibernate with
`ddl-auto: validate` — so a successful start proves the `iv_history` **entity matches the
migrated schema**.

```bash
cd backend
mvn spring-boot:run
```

Look for these lines in the log (the key ones):

```
o.f.core.internal.command.DbMigrate   : Migrating schema "public" to version "4 - iv history"
o.f.core.internal.command.DbMigrate   : Successfully applied 1 migration to schema "public", now at version v4
com.terminalone.TerminalOneApplication: Started TerminalOneApplication in ~2s
```

If the migration or entity mapping were wrong, the app would fail to start here (Flyway
error, or a Hibernate `SchemaManagementException`).

Confirm liveness in another terminal:

```bash
curl -s localhost:8080/api/health          # -> {"status":"UP"}
```

## 3. Inspect the migrated schema

```bash
docker exec t1-pg psql -U terminalone -d terminalone -c "\d iv_history"
docker exec t1-pg psql -U terminalone -d terminalone \
  -c "select version, description, success from flyway_schema_history order by installed_rank;"
```

Expected — note the unique constraint that makes the daily job idempotent:


## 4. Exercise the AC5 IV-history endpoints

Log in with the seeded account (defaults `trader / changeme`, overridable via
`APP_USER_USERNAME` / `APP_USER_PASSWORD`) and capture the JWT:

```bash
BASE=http://localhost:8080
TOKEN=$(curl -s -X POST "$BASE/api/auth/login" -H 'Content-Type: application/json' \
  -d '{"username":"trader","password":"changeme"}' \
  | sed -E 's/.*"token":"([^"]+)".*/\1/')
```

**Read the series** (empty until the job records something):

```bash
curl -s "$BASE/api/marketdata/iv-history/AAPL" -H "Authorization: Bearer $TOKEN"     # -> []
```

**Seed one reading** directly (proves the read path + persistence without needing a live
market-data token; the real job writes rows exactly like this):

```bash
docker exec t1-pg psql -U terminalone -d terminalone -c \
  "insert into iv_history (symbol, as_of_date, atm_iv, underlying_price, atm_strike, expiration, recorded_at)
   values ('AAPL','2026-06-30',0.2845,201.5,200,'2026-08-21', now())
   on conflict (symbol, as_of_date) do update set atm_iv = excluded.atm_iv;"

# lowercase symbol proves the controller normalizes to AAPL:
curl -s "$BASE/api/marketdata/iv-history/aapl" -H "Authorization: Bearer $TOKEN"
# -> [{"symbol":"AAPL","asOfDate":"2026-06-30","atmIv":0.2845,"underlyingPrice":201.5,
#      "atmStrike":200.0,"expiration":"2026-08-21"}]
```

**Trigger the accumulation job on demand** (the same code path the post-close scheduler
runs). With no positions and no `MARKETDATA_TOKEN` it records nothing and skips nothing —
and, importantly, does not crash:

```bash
curl -s -X POST "$BASE/api/marketdata/iv-history/run" -H "Authorization: Bearer $TOKEN"
# -> {"asOfDate":"2026-07-02","recorded":0,"skipped":[]}
```

To see it record real readings: add positions
(`POST /api/portfolio/positions`, or via the desktop console), set `MARKETDATA_TOKEN` in
`backend/.env`, then re-run. Each distinct underlying with an invertible ATM quote yields one
upserted row; unpriceable symbols land in `skipped` (never a zero/NaN row).

**Auth is enforced** (no token → 401):

```bash
curl -s -o /dev/null -w "%{http_code}\n" "$BASE/api/marketdata/iv-history/AAPL"     # -> 401
```

## 5. Run the AC5 unit/slice tests

These run on H2 and need no Docker:

```bash
cd backend
mvn test -Dtest='AtmIvCalculatorTest,AtmIvRecorderTest,MarketDataControllerTest'
```

Covers ATM selection + BS inversion (round-trips synthetic-priced contracts back to their
sigma), dedup of underlyings, the skip/degrade paths (unpriceable + vendor-error isolation),
same-day idempotency, and the HTTP endpoints.

## 6. Teardown

```bash
# stop the backend: Ctrl-C in its terminal (or)
pkill -f 'spring-boot:run'

docker compose down          # stop Postgres, keep the data volume
docker compose down -v       # stop Postgres AND wipe data → next boot replays V1..V4 from scratch
```

## About the scheduled job

The daily run is wired via `@Scheduled` (`AtmIvRecorder`) and enabled by
`SchedulingConfig` (`@EnableScheduling`). It fires post US close on weekdays; override the
cron with `IV_HISTORY_CRON` (default `0 15 16 * * MON-FRI`, zone `America/New_York`):

```bash
IV_HISTORY_CRON='0 15 16 * * MON-FRI'      # sec min hour dom mon dow
```

Use the `POST /api/marketdata/iv-history/run` endpoint above to exercise the exact same path
on demand without waiting for the schedule.
